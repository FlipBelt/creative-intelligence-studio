# 交付、验证与业务确认

## 当前收口规则（2026-10-29）

- 普通软件任务完成适用自动检查和关键路径验证，结果可核实且无阻断问题，即按本次范围收口；不统一要求额外人员或专门全套真人 UAT。缺核心功能、具体权限或数据问题仍须解决。
- 代码、文档和方案交付不追加上线或真实凭据配置门槛；任务承诺上线时，仍须发布证据、来源版本一致和最小线上检查。技术验证、发布证据与用户业务决定分别记录，未执行的检查不能写通过。
- 体验及采用效果在实际工作中反馈，Bug 单独跟进。复用适用的已有证据；可选工具、上游故障不阻塞独立主流程，无新诊断不重复重连或全流程检查。
- 真实权限/撤权、数据准确性、恢复、不可逆操作、采购付款、素材许可、内容批准及持久授权/凭据要求保留。Mock 或界面演示不能证明真实身份、许可、登记或审批，真实内容进入 Final 仍需有权人员批准。
- 本规则不授予部署、迁移、权限扩展、业务写入或外部发布许可；明确暂停仍暂停。下方历史记录保留，其一般视觉/体验待验描述不再是普通软件技术任务的统一前置。

## 已实现范围的关键路径检查

按本次交付涉及的能力选择下列场景并留存可核实结果，不要求每次跑完整 MVP；未实现的真实接入能力保持未实现。其中内容批准属于业务决定，技术测试只验证其机制。

| 场景 | 操作 | 预期 |
|---|---|---|
| 完整闭环 | 使用一款有正式来源产品创建Brief、选参考、确认方向、生成并审核 | Final可定位知识/需求/方向/产物版本 |
| 未知字段 | 绑定缺失材料或性能信息的产品 | 保持未知，不生成无证据卖点 |
| 样品覆盖 | 加入本项目特殊颜色 | 与正式知识分开，范围只在本项目 |
| 改变上游 | 方向确认后修改产品/需求 | 提示旧Instruction过期，原产物仍可溯源 |
| 生成重复 | 连续提交或网络超时后恢复 | 无重复业务任务；无法确认供应商状态时不盲目重发 |
| 知识不可用 | 断开知识服务 | 时间/缓存来源明确，不能伪装最新 |
| 文件失败 | 模拟NAS不可用或中途写入失败 | 不生成可用Final记录，恢复可控 |
| 任务断流 | 页面重连或刷新 | 读取真实状态，不捏造成功与百分比 |
| 人工决定 | AI建议通过但人工淘汰 | 不进入Final，决定与版本记录可查 |
| 权限边界 | 无权限访问其他项目/预览/事件 | 不泄露元数据或媒体 |
| 视觉与键盘 | 目标尺寸、200%缩放、Tab、弹层、reduced-motion | 无遮挡，焦点可见，关键操作可达 |
| 中文编辑 | 输入法组合、错误后重试 | 不误提交，不丢Brief |

每次相关检查记录执行方式、日期、具体版本、结果和缺陷 ID。可自动验证的场景由适用测试或浏览器检查完成；真实授权、许可、恢复和内容批准使用对应真实证据，不能用合成夹具代替。一般视觉与使用体验在实际工作中反馈，无须新增常驻人工验收任务。
